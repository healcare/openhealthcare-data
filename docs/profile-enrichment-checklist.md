# Existing-data profile enrichment checklist

Use with SCALABLE-PROFILE-ENRICHMENT.md and DATA-CONTRIBUTION-CONTRACT.md. This checklist adds no schema or infrastructure.

1. Select the existing bundle ID/import key and canonical path; check revisions/newer evidence. Do not bulk-rename routes.
2. Keep three outputs separate: profile-ready import content, selected public evidence/corrections, and repository-only research.
3. For each claim record a stable key, wording/value, person/location scope, source ID and URL, observation/retrieval date, method, evidence status, editorial disposition, and any superseded-claim link.
4. Write a short intro and optional original story; aim for three/four useful glance items. Add distinctive facts/sections only when sourced and nonrepeating. Omit missing fields; no filler or promotional quality claims.
5. Keep clinical care, coaching and education distinct. Put intake, fees, insurance and availability in dated access. Keep conflicts beside the affected fact; do not infer a replaced phone or appointment capacity.
6. Inspect portrait identity and dimensions; record source page, exact asset URL/host, check date, local path and stated/unknown use terms. Reuse unchanged reviewed assets when the source URL is unchanged. Ordinary previews do not approve derivatives.
7. Preserve permanent IDs, canonical paths, aliases, publication/review/indexing flags, newer evidence and unresolved conflicts.
8. Validate changed records, source IDs, route uniqueness, local image delivery, accessible source links/alt, metadata, no third-party media requests before activation, and desktop/mobile presentation.
9. Report applied changes, held candidates, evidence gaps, checks, blockers and sync. Never present technical validation as human or authority review.
