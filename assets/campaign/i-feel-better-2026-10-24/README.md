- Import and serve locally, using the existing image optimization and caching conventions. Do not hotlink GitHub at runtime or add third-party requests, cookies or trackers.
- Generate appropriately sized responsive variants; do not send the full 1536-pixel export to a small phone display unnecessarily. Compress further where visual inspection confirms the lettering and art remain crisp.
- Lazy-load below-the-fold artwork and reserve its aspect ratio so it causes no layout shift. Treat any above-the-fold image according to actual loading priority; do not preload all four.
- Use meaningful alt text that includes the embedded “I feel better — OpenHealthcare.org” message when the image conveys it. Suggested example: “I feel better — OpenHealthcare.org, over painted blue skies and clouds.” Adapt descriptions to each image. If nearby accessible text already provides the same message and the art is purely decorative, use empty alt text instead of repetitive announcements.
- Check screen-reader output, appropriate image semantics, text contrast/readability, no clipped lettering at mobile widths or zoom, and no unnecessary focus targets.
- Verify the actual chosen mobile/desktop image resources, transferred bytes, lazy loading and layout stability. Compare before/after performance on affected pages under the same conditions; report measured results and limits, not an unverified speed guarantee.
- Run applicable existing project checks and focused browser/accessibility checks. Preserve provider data, permanent URLs, review/indexing state and unrelated work.

Report the data commit consumed, placements, optimized sizes, accessibility/performance results, and app commit. Implementation is authorized; publication remains a separate action. Do not deploy.
